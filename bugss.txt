Here are the most common reasons why these specific sections break and how to fix them:
1. Container Overflow & Unbounded Layout Trees

    The Symptom: Tables, macro breakdown bars, or complex exercise sets flex uncontrollably, overflow the screen horizontally, or overlap adjacent cards.

    Why it Happens: Deeply nested dynamic structures (like exercise set rows or daily meal/macro tables) often lack explicit flex constraints (min-w-0, overflow-x-auto) or rely on fixed pixel widths that break responsively.

    The Fix:

        Wrap dynamic tables or multi-column set inputs in a container with overflow-x-auto w-full.

        Ensure parent flex containers use min-w-0 (in Tailwind/flexbox, standard flex children defaults to min-width: auto, preventing them from shrinking below content size).

2. Tailwind / CSS Scope & Asset Ingestion

    The Symptom: Standard elements (buttons, inputs, cards) lose all margins, padding, or theme colors, defaulting to standard HTML browser styles.

    Why it Happens:

        Unconfigured Tailwind @content paths in tailwind.config.js or missing PostCSS build setup.

        Dark mode / CSS variables not injected at the root level (<html> or <body>).

    The Fix:

        Check tailwind.config.js / vite.config.ts to ensure paths cover all component folders (e.g., ./src/**/*.{js,ts,jsx,tsx}).

        Verify global CSS styles (globals.css / index.css) correctly declare :root variables and dark mode classes (.dark).

3. Grid vs. Flex Misconfiguration on Complex Forms

    The Symptom: Exercise weight/reps inputs or macro targets break onto new lines awkwardly or misalign across columns.

    Why it Happens: Mixing inline flex, absolute positioning, or manual inline styles inside repeating mapped loops (.map()) instead of using CSS Grid.

    The Fix:

        Replace custom percentage width logic in table rows with grid grid-cols-[repeat(...)] or explicit subgrid structures.

        Standardize form rows using fixed grid column definitions:
        TypeScript

        // Example: Reps / Weight / RPE set row
        <div className="grid grid-cols-12 gap-2 items-center">
          <div className="col-span-1">Set 1</div>
          <div className="col-span-4"><Input placeholder="Weight" /></div>
          <div className="col-span-4"><Input placeholder="Reps" /></div>
          <div className="col-span-3"><Button size="sm">Log</Button></div>
        </div>

4. Missing UI Primitive States (Collapsible / Modal Portals)

    The Symptom: Dropdown menus, set options, or template builder drawer popovers appear behind main panels or offset in random corners.

    Why it Happens: Radix UI / Shadcn / Headless UI portals rendering without proper z-index stacking context or inside parent containers with overflow: hidden.

    The Fix: Ensure portals anchor directly to document.body or explicitly set standard z-50 / z-100 layer tokens.

Key Diagnostic Steps

    Inspect Element Constraints: Right-click the broken UI element in Developer Tools and check if an outer wrapper has an unintended height, width: max-content, or missing flex-1.

    Check Global CSS Ingestion: Ensure your main entry file imports the top-level stylesheet (import './globals.css').

    Validate Theme Context: If using Next.js / React providers (ThemeProvider), verify that the root component is wrapped correctly without rendering raw unstyled server component fallbacks.
